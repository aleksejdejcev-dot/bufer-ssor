# «Буфер Ссор» — ИИ-медиатор для пар в конфликте

«Буфер Ссор» — это Telegram Mini App и бот-ассистент, помогающий парам экологично и безопасно разбирать разногласия с помощью искусственного интеллекта (Sber GigaChat / Google Gemini).

---

## 🔒 Архитектура конфиденциальности и безопасности

### 1. Строгий информационный барьер
* **Изоляция данных:** Партнёры описывают конфликт независимо (текстом или голосовыми сообщениями). Ни один из партнёров никогда не видит сырой текст или аудиозапись другого.
* **Обезличенные гипотезы:** При генерации персональной карточки модель получает **только** собственную версию пользователя, его собственный анализ и абстрактную эмоциональную гипотезу («усталость», «желание быть услышанным»). Любые факты, секреты, долги или переписки второго партнёра физически изолированы.
* **Нулевой лог сырых данных:** Все входящие сообщения шифруются ключом Fernet в оперативной памяти. После формирования карточек зашифрованные исходники безвозвратно удаляются из базы данных.

### 2. Защита при угрозах и насилии (Протокол High Risk)
* При обнаружении признаков физического/психологического насилия, преследования, угроз, шантажа или страха партнёра, статус сессии переводится в `high`.
* **Мгновенная блокировка:** Модель полностью прекращает генерацию обычных советов по примирению (в таких ситуациях они опасны).
* **Нейтральные push-уведомления:** В чат Telegram-бота приходит исключительно нейтральное сообщение: *«Ваш разбор готов»*. Экстренная информация никогда не отправляется в открытый чат мессенджера.
* **Экстренные контакты:** Внутри Mini App обоим партнёрам отображается идентичный нейтральный экран с телефонами проверенных экстренных служб:
  * **112** — Единый номер экстренных служб (круглосуточно, бесплатно).
  * **8-800-7000-600** — Всероссийский телефон доверия для женщин, пострадавших от насилия.
* **Кнопка «Быстро закрыть» (Panic Button):** В интерфейсе Mini App размещена заметная кнопка быстрого закрытия, позволяющая в одно касание закрыть приложение Telegram WebApp и очистить экран.

> [!WARNING]
> **Риск физического доступа к экрану:**
> Если ваш партнёр имеет доступ к вашему устройству или может внезапно заглянуть в экран телефона, соблюдайте осторожность:
> 1. Используйте кнопку **«Быстро закрыть»** при малейшем подозрении на небезопасную обстановку.
> 2. Установите пароль / Face ID на вход в приложение Telegram.
> 3. Открывайте разборы только тогда, когда находитесь в уединении и безопасности.

## 🤖 Подключение и настройка Сбер GigaChat (Этап 3.5)

Архитектура проекта поддерживает бесшовное переключение провайдеров ИИ (`LLM_PROVIDER=gigachat` или `LLM_PROVIDER=gemini`) через абстрактный интерфейс `LLMProvider`.

### 1. Получение ключа авторизации (GIGACHAT_CREDENTIALS)
1. Зарегистрируйтесь на портале [Сбер Салют для разработчиков](https://developers.sber.ru/studio).
2. Создайте проект (физическое лицо, ИП или юрлицо) и подключите сервис GigaChat API.
3. В разделе настроек проекта скопируйте **Авторизационные данные** (Base64-строка, объединяющая Client ID и Client Secret).
4. Укажите ключ в файле `.env`:
   ```bash
   LLM_PROVIDER=gigachat
   GIGACHAT_CREDENTIALS=<твой_ключ_авторизации>
   GIGACHAT_SCOPE=GIGACHAT_API_PERS   # GIGACHAT_API_PERS для физлиц, GIGACHAT_API_B2B для ИП/ООО, GIGACHAT_API_CORP для корпораций
   GIGACHAT_MODEL=GigaChat-3-Ultra    # Основная модель (или GigaChat-Pro, GigaChat)
   ```

### 2. Установка доверенных корневых сертификатов Минцифры РФ (TLS)
API GigaChat использует сертификаты Национального удостоверяющего центра Минцифры РФ. Для безопасной работы **без отключения проверки TLS** проект использует бандл сертификатов `backend/certs/russian_trusted_root_ca.pem`.

### 3. Проверка безопасности и поиск утечек перед коммитом
Перед выполнением любого коммита обязательно выполните ручное сканирование репозитория утилитой Gitleaks:
```bash
gitleaks dir . --redact -v
```
Для автоматической проверки при каждом коммите установите хуки:
```bash
pre-commit install
```

#### На macOS:
Сертификаты уже скачаны в проект. Чтобы система доверяла им глобально:
```bash
sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain backend/certs/russian_trusted_root_ca.pem
```

#### В Docker:
В `Dockerfile` бэкенда добавьте установку сертификатов:
```dockerfile
COPY backend/certs/russian_trusted_root_ca.pem /usr/local/share/ca-certificates/russian_trusted_root_ca.crt
RUN update-ca-certificates
```

В `.env` путь к бандлу задается переменной:
```bash
GIGACHAT_CA_BUNDLE=backend/certs/russian_trusted_root_ca.pem
GIGACHAT_INSECURE=0 # Режим verify_ssl_certs=False запрещен в продакшене!
```

### 3. Просмотр доступных моделей и баланса токенов
В репозитории есть утилита `scripts/list_models.py` для быстрой проверки подключения и остатка токенов:
```bash
python scripts/list_models.py
```
Вывод покажет баланс токенов по тарифам (`GigaChat-Ultra`, `GigaChat-Pro`, `GigaChat`) и список доступных моделей.

### 4. Голосовые сообщения
- **GigaChat**: аудиовход не поддерживается нативно. Бот отклоняет голосовые сообщения сразу до скачивания с уведомлением: «Голосовые пока недоступны, отправь, пожалуйста, текстом».
- **Gemini**: поддерживается прямая мультимодальная передача аудио (`audio/ogg`, `audio/mp3`) в модель.

### 5. Правовой статус и обработка данных
- **ИИ-провайдеры**: GigaChat (серверы в РФ) или Gemini (серверы Google).
- **База данных**: Supabase (AWS eu-central, Франкфурт, не РФ). План миграции на российские PostgreSQL-кластеры (Selectel / Yandex Cloud) документирован в `docs/MIGRATION_RU_DB.md`.
- **Юридический статус**: Юридический аудит проекта не проводился. Тексты оферты и политики конфиденциальности являются черновиками и требуют согласования с юристом до запуска в коммерческую эксплуатацию. Чеклист вопросов для юриста: `LEGAL_CHECKLIST.md`.

### 6. Платежи (план реализации для Этапа 5)
Боевые платежи отключены до Этапа 5. В рамках Этапа 3.6 подготовлена схема данных и криптографического хэширования без обработки реальных транзакций.
- **Схема интеграции**: Telegram Stars или webhook ЮKassa → проверка подписи/вебхука → генерация псевдонима плательщика `payer_hash` через `HMAC-SHA256(user_id, PAYMENT_HASH_KEY)` → запись в таблицу `payments`.
- **Поля таблицы `payments`**:
  - `id` (UUID, primary key);
  - `payer_hash` (TEXT, NOT NULL) — необратимый хэш Telegram ID плательщика;
  - `couple_id` (UUID, NULLABLE, `ON DELETE SET NULL`) — привязка к паре; при удалении пары или аккаунтов финансовая транзакция сохраняется в обезличенном виде согласно требованиям бухгалтерского и налогового учёта;
  - `provider` (TEXT: `stars` | `yookassa`);
  - `provider_payment_id` (TEXT, NOT NULL, UNIQUE);
  - `amount` (INTEGER, в копейках / звёздах);
  - `currency` (TEXT: `XTR` | `RUB`);
  - `status` (TEXT: `pending` | `succeeded` | `refunded` | `failed`);
  - `created_at` (TIMESTAMPTZ).
- **Изоляция**: Таблица `payments` защищена Row Level Security (RLS) в Supabase с доступом только через `service_role`.

## ⚙️ Пайплайн генерации и Лестница фоллбэков (Этапы 3.2 - 3.5)

1. **Шаг A (Анализатор):** Декомпозирует обе версии, определяет уровень риска (`none`, `elevated`, `high`), скрытые секреты и обезличенные эмоциональные состояния.
   * При блокировке со стороны провайдера (`blocked=True` или отказ модели) сессия автоматически переводится в режим `high` с причиной `provider_refusal` и выдачей безопасных контактов.
2. **Шаги B1 / B2 (Автор карточки):** Генерирует персональную карточку для каждого партнёра (`validation`, `partner_perspective`, `blind_spot`, 2 прикладных `action_scripts`).
   * **Лестница фоллбэков:**
     * (а) До 2 перегенераций с явным указанием ошибок (при `blocked` — максимум 1 повтор);
     * (б) Безопасный режим вызова с пустой гипотезой о партнёре;
     * (в) Замена проблемных полей случайным статическим нейтральным текстом из `config/fallbacks.py`.
3. **Шаг C (Автор общего итога):** Формирует единый нейтральный итог на уровне местоимения «вы» (динамика, ритуал, стартовая фраза). Любые упоминания ролей («один/другой/ты») и слово «чай» строго запрещены.
4. **Шаг D (Проверка утечек):** Детектор утечек сопоставляет разборы со списками секретов и сырыми версиями.
5. **Валидация перед записью в БД:** Весь сформированный JSON прогоняется через морфологический стеммер (Snowball / pymorphy3), проверяя отсутствие психологических штампов и пустых полей.

## 🛠️ Запуск проекта

### Локальный запуск бэкенда:
```bash
source .venv/bin/activate
PYTHONPATH=backend uvicorn main:app --host 0.0.0.0 --port 8000
```

### Запуск фронтенда (Telegram Mini App):
```bash
cd frontend
npm run dev
```

### Запуск тестов на GigaChat:
```bash
source .venv/bin/activate
PYTHONPATH=backend python backend/tests/run_samples.py --provider gigachat --model GigaChat-3-Ultra
```

### Сравнение результатов двух прогонов:
```bash
PYTHONPATH=backend python backend/tests/run_samples.py --compare backend/tests/out_gemini_....json backend/tests/out_gigachat_....json
```
